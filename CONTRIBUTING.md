# Contributing to SciDraft

Thank you for your interest in improving SciDraft.

Contributions such as bug fixes, documentation improvements, accessibility enhancements, and scientific-writing features are welcome.

## Before contributing

- Check the existing issues to see whether the problem or suggestion has already been reported.
- For substantial changes, open an issue first to discuss the proposed approach.
- Keep changes focused and consistent with the existing theme design.

## Development

1. Fork the repository.
2. Clone your fork.
3. Make your changes on a separate branch.
4. Test your changes with a compatible Hugo installation.
5. Run the example site locally and check the affected features.
6. Submit a pull request describing the changes and how you tested them.

Use the included `exampleSite/` to verify theme changes where applicable.

## Reporting issues

When reporting a bug, include:

- The Hugo version (`hugo version`)
- Steps to reproduce the issue
- Expected and actual behavior
- Relevant error messages or screenshots

Do not include passwords, API keys, or other sensitive information in public issues.

## Documentation

Please update the README or relevant examples when your change affects installation, configuration, or user-facing behavior.

## License and attribution

By contributing, you agree that your contributions may be distributed under the project's applicable license. Ensure that any third-party code or assets you contribute are compatible with the project's licensing requirements.
